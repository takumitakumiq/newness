# Copilot開発フロー（MATSU）

このドキュメントは、MATSU（Django/DRF + Next.js）を GitHub Copilot Chat で効率よく、安全に開発するための「運用フロー」を定義します。

前提: VS Code + GitHub Copilot 拡張が有効。

---

## 1. 基本方針（これだけ守る）

- 1チャットで全部やらない：**役割（サブエージェント）分割**で並列に進める
- 1PR=1目的：変更を小さくして回帰を減らす
- まず調査→次に実装→最後にテスト/レビュー：順番を固定して事故を減らす

---

## 2. 推奨「4役」運用（サブエージェント運用）

同時に複数のチャット（タブ）を開き、それぞれに役割を固定して依頼します。

### 役割A: 仕様/PM（受け入れ条件を作る）
目的: 要件をAC（Acceptance Criteria）に落とす。

出力:
- 目的（Why）
- 変更範囲（In/Out）
- AC（箇条書き）
- リスク/ロールバック

### 役割B: 調査（触るべきファイルを特定）
目的: どこを触ると最短で実現できるか。

出力:
- 関連ファイル候補（優先度順）
- 既存仕様/既存API
- 影響範囲（フロント/バック/DB）

### 役割C: 実装（最小差分でパッチ）
目的: 変更を小さく、互換性を壊さずに実装する。

出力:
- 実装方針（2〜3案）
- 選択案のパッチ
- 例外/エラー設計

### 役割D: テスト/レビュー（回帰観点を洗う）
目的: 壊れやすい箇所を最初に潰す。

出力:
- 追加すべきテスト
- 手動確認手順
- セキュリティ/権限/入力バリデーション観点の指摘

---

## 2.1 runSubagent（サブエージェント呼び出し）の使いどころ

この環境では、チャット側から「runSubagent」を使って、別の役割に“調査/整理”を委任できます。

### いつ使う？（おすすめ）

- **要件が曖昧**: PM役にAC作成を委任してブレを止める
- **関連箇所が多そう**: 調査役に「関連ファイル候補と根拠」を委任して探索を短縮する
- **実装方針で迷う**: 実装役に2〜3案比較を委任して意思決定を速くする
- **安全性を担保したい**: レビュー役に権限/入力検証/例外処理の抜けを委任する

### 注意点（運用ルール）

- subagentは**状態を引き継がない**前提で、プロンプトに必要情報を埋め込む
- 依頼は「1回で1目的」に絞る（調査と実装を混ぜない）
- 出力フォーマットを固定（例: 関連ファイル→根拠→影響範囲→次の確認）

---

## 2.2 利用可能なサブエージェント

- `Plan`: マルチステップな計画・分解・運用手順の整理が得意

（他のエージェントが追加された場合も、このセクションに追記して一覧化します）

---

## 2.3 例: 「スタッフチャットが接続中のまま」初動

最初の一手は “調査の分解” です。runSubagent（Plan）には次を投げるのが安定です。

- 目的: 原因候補を3つに絞るための「調査手順」を作る
- 入れる情報: 再現手順、期待、環境（URL/ポート/NEXT_PUBLIC_API_URL）、ログ（可能なら）

次に、手順に沿って「関連ファイル（フロント: WS接続、バック: consumers/routing）」を確認していきます。

---

## 3. 進め方（テンプレ）

1) **やりたいことを1行で宣言**
- 例: 「スタッフチャットの接続が『接続中』のままになるのを直す」

2) 仕様/PMに投げる（ACを作る）
- ACがOKになるまで実装に入らない

3) 調査に投げる（関連ファイル・根拠を出す）
- 変更対象が揃ってから実装に入る

4) 実装（小さくパッチ）
- 互換性が怪しい場合は段階移行（両対応）

5) テスト/レビューで確認
- “直った”ではなく “壊れてない”まで確認

---

## 4. MATSU固有の重要ポイント

- フロントは `NEXT_PUBLIC_API_URL` で REST/WebSocket の接続先を決めます（未設定だと接続が不安定になります）。
- 重要操作は `request.user` で操作者を確定し、クライアント入力を信用しません（FEATURE_INSTRUCTION.md の共通要件参照）。

---

## 5. よくある依頼の“型”

- バグ修正: 「再現手順 → 原因候補 → 最小修正 → 回帰観点」
- 機能追加: 「AC → 既存設計に沿う → API→UI→運用」
- 仕様調整: 「互換性・移行・ロールバックを先に決める」
